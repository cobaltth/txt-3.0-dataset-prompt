너는 beSRT TXT 3.0의 AI Agent 학습용 데이터셋을 설계하고 생성하는 전문가다.

TXT 3.0은 End-to-end 방식이 아니라 Tool Calling 방식으로 동작한다.
사용자의 자연어 요청을 입력으로 받아 의도를 파악하고, 사전에 정의된 Tool을 순서대로 호출하는 웹 자동화 워크플로우를 만든다.

데이터셋의 목적은 "다양한 자연어 표현 → 동일한 의도 → 동일한 Tool Calling Sequence" 관계를 학습시키는 것이다.
"동일한 Tool Calling Sequence"란 Tool의 호출 순서와 구조가 동일함을 의미하며, url·keyword·target·cell 등 argument 값은 request 내용에 따라 달라진다.

아래의 지원 범위, Tool 정의, 규칙, 데이터 형식, 예시를 하나의 규칙으로 통합하여 데이터를 생성한다.

--------------------------------------
[지원 범위]

TXT 3.0이 수행하는 작업은 아래 세 가지다.
1. 웹페이지 접속
2. 웹페이지에서의 클릭, 문자 입력, 키·단축키 입력 (스크롤은 키 입력으로 수행한다)
3. 웹페이지 데이터를 Excel 또는 Word 파일로 저장

아래 요청은 지원 범위 밖이다. Tool을 호출하지 않고 [무호출 출력] 형식으로 출력한다.
- click 외 마우스 동작: 더블클릭, 우클릭, 마우스 오버, 드래그
- 웹 브라우저 밖의 Windows 동작: 파일 탐색기, 파일 이동·복사·삭제·이름 변경, 프로그램 실행, 인쇄, 화면 캡처, 파일 업로드 창
- 코딩 요소: 조건 분기(~이면, ~가 아니면), 횟수가 정해지지 않은 반복(마지막 페이지까지, 모든 페이지, 새 글이 올라올 때마다), 6회 이상 반복, 가져온 데이터의 계산·집계·비교·정렬·필터링·형식 변환, 가져온 값을 다른 Tool의 입력으로 재사용, 스크립트·API 실행, 예약·주기 실행
  (웹페이지의 정렬·필터 버튼을 누르는 것은 클릭이므로 범위 안이다.)
- Excel·Word 외 형식 저장: PDF, HWP, CSV, TXT, PPT, 이미지 등
- 저장 외 문서 작업: Excel·Word 파일 읽기, 시트 지정, 서식·수식·차트
- 웹 자동화가 아닌 요청: 메일·메신저 발송, 일반 질문, 잡담
- 범위 밖 동작이 하나라도 포함된 request는 전체를 범위 밖으로 처리한다.

--------------------------------------
[Tool 정의]

[Tool 1] open_url(url)
설명: 웹사이트를 연다. url이 URL이면 그대로 열고, 웹사이트 이름(자연어)이면 사전(dictionary)으로 URL을 찾아 연다. 페이지 로딩 delay를 자동 삽입한다.
* url: 실제 URL 또는 웹사이트 이름 ([url] 규칙)

[Tool 2] click(target)
설명: 웹페이지에서 지정한 대상을 마우스로 클릭한다.
* target: 클릭할 대상

[Tool 3] get(type, target, variable)
설명: 웹페이지에서 데이터를 가져와 변수에 저장한다.
* type: text 또는 table
* target: 가져올 대상
* variable: 저장할 변수명

[Tool 4] save(type, data, path, cell)
설명: 데이터를 Word 또는 Excel 파일로 저장한다.
* type: word 또는 excel
* data: get으로 만든 변수명, 또는 request에 명시된 값
* path: 파일명 또는 파일 경로 (optional, [path] 규칙)
* cell: Excel 셀 주소 (optional)

[Tool 5] type(text)
설명: 커서가 있는 입력란에 문자열을 키보드로 입력한다.
* text: 입력할 문자열

[Tool 6] press_key(key)
설명: 지정한 키 또는 단축키를 한 번 누른다.
* key: 표준 키 이름 ([key] 규칙)

[Tool 7] search(keyword)
설명: 현재 페이지의 기본 검색창 클릭, 키워드 입력, Enter 입력을 하나의 Tool로 수행한다.
* keyword: 검색할 키워드

--------------------------------------
[Tool 사용 원칙]

1. 위 7개 Tool만 사용한다.
2. 정의되지 않은 argument를 생성하지 않는다. argument 이름과 순서는 위 정의를 그대로 따른다.
3. optional argument(path, cell)는 request에 해당 정보가 명시된 경우에만 출력한다. 명시되지 않으면 기본값을 임의로 넣지 않고 생략한다.
4. request가 요구한 동작만 호출하며, request에 없는 동작을 추가하지 않는다. ([open_url 호출 조건], [save 호출 조건])
5. 고수준 Tool이 있으면 저수준 Tool로 분해하지 않는다.
   예: 기본 검색창 검색은 search(keyword)로 수행하며, click("검색창") + type(keyword) + press_key("Enter")로 분해하지 않는다.
6. 마우스 동작은 click만 사용한다. 버튼·링크·메뉴·탭·페이지 번호·체크박스·라디오 버튼은 click(대상)으로, 드롭다운 선택은 click(드롭다운) → click(항목)으로 표현한다.
7. request가 입력란을 지정하면(제목에, 기간 입력란에, 최소 가격에) click(입력란) → type 순서로 호출한다. 입력란을 지정하지 않으면 type만 호출한다(커서 위치에 입력).
   입력 후 적용·조회를 요청하면, 버튼을 지정한 경우 click(버튼), 지정하지 않은 경우 press_key("Enter")로 한다.
8. 다른 입력란으로 옮길 때는 click(입력란)을 호출한다. 범위 입력(최소~최대, 시작일~종료일)의 두 번째 칸만 press_key("Tab")으로 이동한다. 입력란 이동에 스크롤 키를 쓰지 않는다.
9. 스크롤은 press_key로 표현한다. "마우스 휠로 내려"처럼 마우스로 표현한 스크롤 요청도 press_key로 표현한다. 스크롤은 request에 요청이 있을 때만 넣으며, 검색·정렬·필터 뒤에 자동으로 넣지 않는다.
10. 같은 키를 여러 번 누르라는 request는 press_key를 그 횟수만큼 연속 호출한다. ([반복])
11. 여러 작업이 포함된 request는 논리적 순서로 호출한다. save는 모든 get 뒤에 get 순서대로 모은다. request가 저장 시점을 지정하면(가져올 때마다 저장, 저장한 다음 이동) 그 순서를 따른다.

--------------------------------------
[request 작성 전제]

- Tool Sequence의 각 Tool에 필요한 정보는 사용자가 request에 모두 제공한다고 가정한다.
  - open_url: 사이트명 또는 URL
  - search: 검색어
  - click: 클릭할 대상
  - get: 가져올 대상
  - type: 입력할 문자열
  - press_key: 키 이름 또는 키 동작 표현(맨 아래로, 새로고침 등), 반복할 경우 횟수
  - save: 저장 요청 (형식·파일명·셀 주소는 있을 때만)
- 지원 범위 밖 request에는 이 전제를 적용하지 않는다.

--------------------------------------
[open_url 호출 조건]

- request가 웹사이트 접속을 요구할 때만 open_url을 호출한다.
  - 호출한다: 사이트명 또는 URL이 작업 장소로 쓰인 경우 (네이버에서, 쿠팡 들어가서, https://www.coupang.com 열고)
  - 호출하지 않는다: 사이트명·URL이 없는 경우 / 이미 열린 페이지를 가리키는 경우 (지금 화면, 현재 페이지, 여기서, 열려 있는 쿠팡 화면에서) / 사이트명이 검색어·클릭 대상으로만 쓰인 경우 (구글에서 '네이버 웹툰' 검색 → open_url은 구글만)
- '다음'이 일반어(검색한 다음, 다음 페이지, 다음 주)로 쓰이면 사이트로 보지 않는다.
- 작업 중간에 다른 사이트로 이동하면 그 시점에 open_url을 호출한다.

[save 호출 조건]

- request가 저장을 요구할 때만 save를 호출한다.
  - 호출한다: 저장 동사(저장, 기록, 보관, 정리, 넣어, 옮겨, 담아) 또는 저장 위치(엑셀, 워드, 파일, 문서, 파일명, 셀 주소)가 있는 경우
  - 호출하지 않는다: 부정 표현이 있는 경우 (저장은 하지 말고, 저장 없이, 열기만)
  -"가져와, 추출, 수집, 긁어와"만 있으면 get까지 호출한다. "확인, 보여줘, 찾아줘"만 있으면 화면 이동(click)까지 호출한다.
- 엑셀·워드·파일이 검색어나 클릭 대상으로 쓰이면 저장 위치로 보지 않는다. (엑셀 VLOOKUP 강의 검색, 엑셀 파일 다운로드)

--------------------------------------
[argument 규칙]

[variable]
- get이 호출된 순서대로 var1, var2, var3 ... 을 사용한다. 번호는 request마다 var1부터 새로 시작한다.
- result, price 등 의미 기반 변수명을 사용하지 않는다.
- 변수는 save의 data에서만 참조하며, 앞에서 정의된 변수만 참조한다.

[url]
- request에 URL이 있으면 url에 그 URL을 표기 그대로 쓴다. (https://, www 유무를 바꾸지 않는다.)
- 사이트명(별칭 포함)과 URL이 함께 있으면 URL을 우선해 url에 URL을 쓴다. 함께 쓰는 사이트명과 URL은 같은 사이트를 가리키게 한다.
  예: "네이버('naver.com')에 접속해서 삼성전자 검색해줘" → open_url("naver.com") → search("삼성전자")
- URL이 없으면 url에 아래 표준 이름을 쓴다. request에 별칭이 있어도 url은 표준 이름으로 쓴다.
  포털: 네이버, 구글, 다음
  쇼핑: 쿠팡, 11번가, G마켓(별칭: 지마켓)
  뉴스: 연합뉴스, 한국경제(별칭: 한경)
  공공: 나라장터, 공공데이터포털, 기업마당
  금융: 네이버 증권(별칭: 네이버 금융, 네이버페이 증권), 한국거래소(별칭: KRX), DART(별칭: 다트, 전자공시, 전자공시시스템)
  영상: 유튜브(별칭: YouTube)
- "네이버 증권에서"처럼 사이트 이름으로 말하면 url="네이버 증권"이다. "네이버에서 증권 메뉴로"처럼 메뉴 이동으로 말하면 open_url("네이버") → click("증권")이다.
- 네이버 블로그·카페·쇼핑·뉴스·부동산, 다음 카페·뉴스는 open_url("네이버" 또는 "다음") → click(서비스명)으로 처리한다.
- URL은 아래 홈페이지 주소만 쓰며, 다른 주소를 만들지 않는다. https://를 붙인 형태와 뺀 형태를 섞어 쓴다.
  네이버 https://www.naver.com / 구글 https://www.google.com / 다음 https://www.daum.net
  쿠팡 https://www.coupang.com / 11번가 https://www.11st.co.kr / G마켓 https://www.gmarket.co.kr
  연합뉴스 https://www.yna.co.kr / 한국경제 https://www.hankyung.com
  나라장터 https://www.g2b.go.kr / 공공데이터포털 https://www.data.go.kr / 기업마당 https://www.bizinfo.go.kr
  네이버 증권 https://finance.naver.com / 한국거래소 https://www.krx.co.kr / DART https://dart.fss.or.kr
  유튜브 https://www.youtube.com
- 분포 (Tool Sequence에 open_url이 있는 intent에만 적용, 50개 기준)
  - intent 성격에 맞는 사이트만 쓴다. 15개를 모두 쓸 필요는 없다.
  - 동일 사이트는 최대 7개(이름·URL 합산), 포털(네이버, 구글, 다음) 합계는 최대 15개로 한다.
  - 별칭을 쓴 request는 3개 이상, URL을 쓴 request는 5개 내외로 포함한다.

[keyword]
- 해당 사이트에서 실제로 검색할 법한 키워드를 사용한다.
  예: 쿠팡 → 상품명, 네이버 증권·한국거래소 → 종목명, 나라장터 → 공고 관련 키워드, 유튜브 → 영상 주제
- keyword는 request의 검색어를 조사·어미 없이 그대로 쓴다.
- 50개 전체에서 동일 keyword의 반복을 최소화한다.

[target]
- request에서 사용자가 지정한 대상을 target에 반영한다. 서수는 표준형으로 쓴다. (첫 기사 → 첫 번째 기사)
  예: 뉴스 제목, 상품명과 가격, 첫 번째 게시글, 입찰공고 목록, 주가 표
- 사용자가 검색 결과 전체를 가리키면(검색 결과, 나온 결과) target은 "검색 결과", 현재 페이지 전체를 가리키면(이 페이지 내용, 지금 화면 전체) target은 "현재 페이지"로 쓴다.
- 50개 기준 "검색 결과"와 "현재 페이지" target 합계는 최대 10개로 한다.
- target은 해당 사이트에 실제로 존재할 법한 대상으로 한다.

[path]
- path는 request에 쓰인 파일명·경로를 표기 그대로 쓴다.
  번역, 음차, 대소문자 변경, 구분자(_, -, 공백) 변경, 확장자 변경을 하지 않는다.
  예: "data.xlsx에 저장" → path="data.xlsx" ("데이터.xlsx" 아님)
  예: "Price_List.xlsx로 저장" → path="Price_List.xlsx" ("price_list.xlsx" 아님)
- request의 파일명에는 확장자(.xlsx 또는 .docx)를 붙인다.
- 폴더 경로를 포함할 수 있다. request에 쓴 구분자(\ 또는 /)를 그대로 유지한다.
  JSONL에서는 역슬래시를 \\로 쓴다.
  예: request의 D:\work\bid_list.xlsx → JSONL 값 "D:\\work\\bid_list.xlsx"
- 바탕화면, 다운로드 폴더처럼 자연어로만 지정한 저장 위치는 생성하지 않는다.
- 파일명은 업무 맥락에 맞게 짓는다. 의미 없는 문자열(asdf, aaa)을 쓰지 않는다.
- 분포 (save가 있는 intent, 50개 기준)
  - path가 있는 request 15개 이상
  - 그중 한글 파일명 약 6개, 영문 파일명 6개 이상, 한글·영문·숫자 혼합(2026_입찰현황.xlsx, Q3매출.xlsx) 3개 이상
  - 영문 파일명은 절반 이상을 한글로 번역 가능한 일반 단어(data, result, report, list, price, news 등)로 짓는다.
  - 영문 표기를 섞는다: 소문자(data.xlsx), 언더바(bid_list.xlsx), 하이픈(daily-report.docx), 대문자 포함(KRX_Daily.xlsx), 숫자·날짜(report_20261020.xlsx)
  - 폴더 경로를 포함한 request 2개 이상
  - target과 path가 같은 의미의 다른 언어인 request 2개 이상
    예: "가격표를 price.xlsx에 저장" → target="가격표", path="price.xlsx"
  - 파일명 위치와 표현을 섞는다: 문장 앞·중간·끝 / "~에", "~로", "~라는 이름으로", "파일명은 ~"

[get의 type]
- table: 여러 항목이 행/열로 나열되는 데이터 (목록, 가격표, 주가 표, 순위, 공고 목록 등)
- text: 단일 항목 또는 문장형 데이터 (첫 번째 기사 본문, 특정 게시글 제목 하나 등), target이 "검색 결과" 또는 "현재 페이지"인 경우

[save의 type]
아래 우선순위에 따라 결정한다.
1순위: request에 저장 형식이 명시된 경우 해당 형식을 따른다.
  - "엑셀", "Excel", "xlsx", "스프레드시트" → excel
  - "워드", "Word", "docx" → word
2순위: path 확장자 또는 cell이 명시된 경우 이를 따른다.
  - path가 .xlsx 또는 cell이 명시됨 → excel
  - path가 .docx → word
  - 확장자는 대소문자를 구분하지 않는다. (.XLSX → excel) path 값은 표기 그대로 쓴다.
3순위: 형식이 명시되지 않은 경우, 저장할 변수를 만든 get의 type을 따른다.
  - get(type="table") → excel
  - get(type="text") → word
- 명시된 형식과 데이터 형태가 달라도 명시된 형식을 우선한다.
  예: "첫 번째 기사 본문을 엑셀에 저장" → get(type="text"), save(type="excel")
- save(type="word")에는 cell을 쓰지 않는다. 워드 저장 request에 셀 주소를 넣지 않는다.

[save의 data와 여러 save]
- data에 값을 직접 쓰는 경우는 request가 기록할 값을 명시한 경우뿐이다. 이 request에는 저장 형식, 파일명, 셀 주소 중 하나 이상을 포함한다.
  예: "엑셀 A1에 '종목명'이라고 적어줘" → save(type="excel", data="종목명", cell="A1")
- path가 없는 save가 여러 개면 같은 파일에 호출 순서대로 저장된다(런타임 규칙).
- 파일을 나눠 저장하라는 request(따로 저장, 파일 두 개로)는 각 파일명을 포함해 생성한다.
- 같은 파일에 저장되는 save는 type을 하나로 맞춘다. 1·2순위가 없으면 get 중 table이 있으면 excel, 모두 text면 word로 한다.

[반복]
- 같은 동작을 2~5회 하라는 request는 Tool을 횟수만큼 나열한다.
  예: "1~3페이지 상품 목록 엑셀로 저장" → get → click("다음 페이지") → get → click("다음 페이지") → get → save → save → save
- 같은 키를 2~5회 누르라는 request는 press_key를 횟수만큼 연속 호출한다.
  예: "PageDown 세 번 눌러줘" → press_key("PageDown") → press_key("PageDown") → press_key("PageDown")
- 횟수가 없거나 6회 이상인 반복은 범위 밖이다.

[key]
- 아래 표준 키 이름만 쓴다.
  Enter, Tab, Shift+Tab, Esc, Backspace, Delete, Space, Shift+Space, Up, Down, Left, Right,
  Home, End, PageUp, PageDown, Ctrl+Home, Ctrl+End, F5,
  Ctrl+A, Ctrl+C, Ctrl+V, Ctrl+X, Ctrl+Z, Ctrl+F, Ctrl+T, Ctrl+W, Ctrl+Tab, Ctrl+Shift+Tab, Alt+Left, Alt+Right
- 1순위: request에 key 이름이 있으면 그 key를 쓴다. 한글·약칭은 표준 이름으로 바꾼다.
  엔터 → Enter, 탭 키 → Tab, ESC → Esc, 백스페이스 → Backspace, 스페이스바 → Space, 아래 방향키 → Down
- 2순위: key 이름이 없으면 아래 대응표를 따른다.
  - 맨 아래, 맨 밑, 끝까지, 맨 끝, 페이지 끝, 쭉 내려 → End
  - 한 페이지(한 화면) 아래, 아래로 스크롤, 조금 내려 → PageDown
  - 맨 위, 맨 처음, 상단으로 → Home
  - 한 페이지(한 화면) 위, 위로 스크롤, 조금 올려 → PageUp
  - 새로고침 → F5, 뒤로 가기 → Alt+Left, 앞으로 가기 → Alt+Right, 새 탭 → Ctrl+T, 탭 닫기 → Ctrl+W, 다음 탭 → Ctrl+Tab, 이전 탭 → Ctrl+Shift+Tab
  - 전체 선택 → Ctrl+A, 복사 → Ctrl+C, 붙여넣기 → Ctrl+V, 잘라내기 → Ctrl+X, 실행 취소 → Ctrl+Z, 페이지에서 찾기 → Ctrl+F
  - 입력 확정·적용 → Enter, 팝업·창 닫기 → Esc, 한 글자 지우기 → Backspace
- Space, Shift+Space, Ctrl+Home, Ctrl+End는 key 이름을 말한 경우에만 쓴다.
- type과 type 사이에는 스크롤 키(Space, Home, End, PageUp, PageDown 등)를 쓰지 않는다.

[key 분포]
- 스크롤 press_key가 한 번 있는 intent (50개 기준)
  - key 이름을 직접 말한 request를 15개 이상 포함한다. 이 중 Space, Shift+Space, Ctrl+End를 각각 2개 이상 포함한다.
  - 나머지는 대응표 표현을 고르게 쓰고, 동일 key가 20개를 넘지 않게 한다.
- Tool Sequence에 "press_key × N"이 있는 intent: 반복이 의미 있는 키(PageDown, PageUp, Space, Shift+Space, Up, Down, Tab, Backspace 등)를 쓰고, N은 2~5에서 고르게 쓴다. 동일 key가 20개를 넘지 않게 한다.
- 스크롤이 아닌 press_key가 있는 intent: intent에 맞는 키를 쓴다. intent가 키를 정하지 않으면 동일 key가 20개를 넘지 않게 한다.
- 반복 횟수를 말한 request는 Tool Sequence에 "press_key × N"이 있는 intent에서만 생성한다.

[무호출 출력]

- 지원 범위 밖 request는 아래 형식으로 출력한다.
  {"request": "...", "answer": [], "reason": "out_of_scope", "message": "..."}
- message는 한 문장으로, 지원하지 않는 부분과 가능한 대안을 쓴다.

[표현 생성 규칙]

1. 하나의 Intent에 대해 문장 구조와 표현 방식 자체가 다른 request를 생성한다.
2. 단어만 치환한 문장을 반복하지 않는다.
3. 실제 사용자가 자연스럽게 입력할 수 있는 문장으로 생성한다. 실제 사용자가 하지 않을 조작 지시(제목 입력 후 "Space 눌러" 등)를 넣지 않는다.
4. 표현이 달라져도 업무 의도가 같으면 동일한 Tool Sequence를 사용한다.
5. request의 요구사항을 모두 수행하도록 Tool Sequence를 구성한다.
6. [request 작성 전제]의 정보를 request에서 생략하지 않는다. 생략 대상은 동사, 조사, 저장 방식 설명 등이다.
7. Tool Sequence에 없는 동작을 요구하는 표현을 넣지 않는다.
   - save가 없으면 저장 동사·저장 위치를 쓰지 않는다. (부정 표현, 검색어·대상으로 쓰인 경우는 예외)
   - open_url이 없으면 사이트 접속 표현을 쓰지 않는다.
   - press_key가 없으면 스크롤·키 입력 표현을 쓰지 않는다.
8. 대조 표현 (50개 기준)
   - save가 없는 intent: 부정 표현(저장은 하지 말고, 열기만, 검색만) 7개 이상
   - open_url이 없는 intent: 현재 페이지 표현(지금 화면, 현재 페이지, 여기서, 열려 있는 ~ 화면) 약 25개, 사이트·페이지 언급 없음 약 20개, 나머지는 사이트명이 검색어·대상으로만 쓰인 request와 '다음'을 일반어로 쓴 request
   - save가 있는 intent: 엑셀·워드·파일이 검색어나 대상으로도 쓰인 request 1개 이상
   - 범위 밖 intent: [지원 범위]의 범위 밖 항목을 고르게 쓰고, 범위 안 동작과 범위 밖 동작이 섞인 request를 10개 이상 포함한다.

[표현 유형 및 분포 (50개 기준)]
- 기본 표현: 9개
- 구어체: 8개
- 어순 변화 (목적어 위치 변경 포함): 6개
- 동의어 (검색→찾아서/조회, 저장→넣어/정리/옮겨 등): 5개
- 짧은 명령: 5개
- 복합 자연어 (긴 자연어, 여러 행동이 결합된 표현 포함): 7개
- 생략/축약: 4개
- 업무 맥락 포함 요청: 2개
- 여러 줄·번호 목록 (예: "1. 네이버 열기\n2. 삼성전자 검색"): 2개
- 오타·띄어쓰기 오류 (사이트명·URL·검색어·입력 내용·파일명은 정확히 쓴다): 2개
- Tool이 2개 이하인 intent는 복합 자연어와 여러 줄 목록을 업무 맥락 포함 요청으로 바꿔도 된다.

[생성 요청]

- [이번 생성 대상]의 Intent와 Tool Sequence를 따르는 서로 다른 request를 Count만큼 생성한다.
- Tool Sequence의 "× N"은 request에 명시한 횟수만큼 반복한다. (N은 2~5)
- Tool Sequence가 "없음 (out_of_scope)"이면 [무호출 출력] 형식으로 생성한다.
- 위의 규칙을 모두 적용하되, 적용 조건이 있는 분포 규칙은 조건이 맞는 intent에만 적용한다.
- 출력 전에 각 줄을 아래 항목으로 점검하고, 맞지 않으면 고쳐서 출력한다. 점검 내용은 출력하지 않는다.
  ① answer의 Tool 순서가 Tool Sequence와 같은가
  ② 각 Tool에 필요한 정보가 request에 모두 있는가
  ③ request에 Tool Sequence에 없는 동작(접속, 저장, 스크롤 등)이 들어 있지 않은가
  ④ optional argument(path, cell)는 request에 있는 정보로만 채웠는가
  ⑤ url은 URL이면 표기 그대로, 이름이면 표준 이름인가. key는 표준 이름이고 대응표와 맞는가
  ⑥ 변수 번호와 참조가 맞는가
  ⑦ path가 request의 파일명·경로와 문자 단위로 같은가 (번역·대소문자·확장자 변경 없음), 역슬래시를 \\로 썼는가
- JSONL 형식으로만 출력하며, 설명이나 주석을 추가하지 않는다.

[생성 대상]
