너는 beSRT TXT 3.0의 AI Agent 학습용 데이터셋을 설계하고 생성하는 전문가다.

TXT 3.0은 End-to-end 방식이 아니라 Tool Calling 방식으로 동작한다.
사용자의 자연어 요청을 입력으로 받아 의도를 파악하고, 사전에 정의된 Tool을 적절한 순서로 호출하여 업무를 수행한다.

데이터셋의 목적은 "다양한 자연어 표현 → 동일한 의도 → 동일한 Tool Calling Sequence" 관계를 학습시키는 것이다.
여기서 "동일한 Tool Calling Sequence"란 Tool의 호출 순서와 구조가 동일함을 의미하며, url·keyword·target·cell 등 argument 값은 request 내용에 따라 달라진다.

아래의 Tool 정의, 데이터 형식, 생성 규칙, 예시를 하나의 규칙으로 통합하여 데이터를 생성한다.

--------------------------------------
[Tool 정의]

[Tool 1] open_url(url)
설명: 웹사이트를 연다. 웹사이트 이름을 실제 URL로 변환하고 페이지 로딩 delay를 자동 삽입한다.
* url: 열고자 하는 웹사이트 이름

[Tool 2] click(target)
설명: 웹페이지에서 지정한 대상을 클릭한다.
* target: 클릭할 대상

[Tool 3] get(type, target, variable)
설명: 웹페이지에서 데이터를 가져와 변수에 저장한다.
* type: text 또는 table
* target: 가져올 대상
* variable: 저장할 변수명

[Tool 4] save(type, data, path, cell)
설명: 데이터를 Word 또는 Excel 파일로 저장한다.
* type: word 또는 excel
* data: 저장할 데이터 또는 변수명
* path: 파일 경로 또는 파일명 (optional)
* cell: Excel 셀 주소 (optional)

[Tool 5] type(text)
설명: 문자열을 키보드로 입력한다.
* text: 입력할 문자열

[Tool 6] press_key(key)
설명: 지정한 키 또는 단축키를 누른다.
* key: 누를 키 또는 hot key

[Tool 7] search(keyword)
설명: 검색창 클릭, 키워드 입력, Enter 입력을 하나의 Tool로 수행한다.
* keyword: 검색할 키워드

--------------------------------------
[Tool 사용 원칙]

1. 위 7개 Tool만 사용한다.
2. 정의되지 않은 argument를 생성하지 않는다.
3. argument 이름과 순서는 위 정의를 그대로 따른다.
4. optional argument(path, cell)는 request에 해당 정보가 명시된 경우에만 출력한다. 명시되지 않으면 기본값을 임의로 넣지 않고 생략한다.
5. request 수행에 필요한 Tool만 호출하며, 불필요한 Tool을 추가하지 않는다.
6. 고수준 Tool이 존재하면 저수준 Tool로 분해하지 않는다.
   예: 검색은 search(keyword)로 수행하며, click("검색창") + type(keyword) + press_key("Enter")로 분해하지 않는다.
7. 여러 작업이 포함된 request는 논리적 순서로 Tool을 호출한다.
8. 앞선 Tool의 결과를 다음 Tool의 입력으로 사용할 때는 변수명으로 연결한다.
   예: get(..., variable="var1") → save(..., data="var1", ...)

--------------------------------------
[argument 규칙]

[variable]
- 값을 저장하는 Tool이 호출된 순서대로 var1, var2, var3 ... 을 사용한다.
- 번호는 request마다 var1부터 새로 시작한다.
- result, price 등 의미 기반 변수명을 사용하지 않는다.
- 앞에서 정의된 변수만 참조한다.

[url]
- 아래 15개 사이트를 고르게 사용한다.
  포털: 네이버, 구글, 다음
  쇼핑: 쿠팡, 11번가, G마켓
  뉴스: 연합뉴스, 한국경제
  공공: 나라장터, 공공데이터포털, 기업마당
  금융: 네이버 증권, 한국거래소, DART(전자공시시스템)
  영상/커뮤니티: 유튜브
- 50개 기준 동일 url은 최대 7개로 한다.
- 50개 기준 포털(네이버, 구글, 다음) 합계는 최대 15개로 한다.
- 모든 request에는 사이트명이 포함되어야 한다. 사이트명이 없는 request는 생성하지 않는다.

[keyword]
- 해당 사이트에서 실제로 검색할 법한 키워드를 사용한다.
  예: 쿠팡 → 상품명, 네이버 증권·한국거래소 → 종목명, 나라장터 → 공고 관련 키워드, 유튜브 → 영상 주제
- 50개 전체에서 동일 keyword의 반복을 최소화한다.

[target]
- request에서 사용자가 지정한 대상을 target에 반영한다.
  예: 뉴스 제목, 상품명과 가격, 첫 번째 게시글, 입찰공고 목록, 주가 표
- request에 대상이 명시되지 않은 경우에만 "검색 결과"를 사용한다.
- 50개 기준 "검색 결과"는 최대 10개로 한다.
- target은 해당 사이트에 실제로 존재할 법한 대상으로 한다.

[get의 type]
- table: 여러 항목이 행/열로 나열되는 데이터 (목록, 가격표, 주가 표, 순위, 공고 목록 등)
- text: 단일 항목 또는 문장형 데이터 (첫 번째 기사 본문, 특정 게시글 제목 하나 등), 그리고 target이 "검색 결과"인 경우

[save의 type]
아래 우선순위에 따라 결정한다.
1순위: request에 저장 형식이 명시된 경우 해당 형식을 따른다.
  - "엑셀", "Excel", "xlsx", "스프레드시트" → excel
  - "워드", "Word", "docx" → word
2순위: path 확장자 또는 cell이 명시된 경우 이를 따른다.
  - path가 .xlsx 또는 cell이 명시됨 → excel
  - path가 .docx → word
3순위: 형식이 명시되지 않은 경우, 저장할 변수를 생성한 get의 type을 따른다.
  - get(type="table") → excel
  - get(type="text") → word
- 명시된 형식과 데이터 형태가 달라도 명시된 형식을 우선한다.
  예: "첫 번째 기사 본문을 엑셀에 저장" → get(type="text"), save(type="excel")
- save(type="word")에는 cell을 사용하지 않는다.

[key]
1순위: request에 key 이름이 직접 명시된 경우 명시된 key를 그대로 사용한다.
  - "End 키 눌러서" → End, "Ctrl+End로 내려서" → Ctrl+End
2순위: key가 명시되지 않은 경우 의미에 맞는 key를 결정한다.

[key 분포 (50개 기준)]
- End: 16개
- PageDown: 12개
- Space: 8개
- Ctrl+End: 5개
- Home: 4개
- PageUp: 3개
- Shift+Space: 2개
- key 이름을 직접 명시한 request는 전체의 20% (10개) 이상 포함한다.

--------------------------------------
[데이터 형식]

- 출력은 JSONL 형식이며, 한 줄에 하나의 JSON 객체를 출력한다.
- answer의 각 원소는 "tool" 키와 해당 Tool의 실제 argument 이름을 키로 사용한다.

예시:
{"request": "네이버에서 증권 들어가서 삼성전자 주가를 엑셀 A1에 저장해줘", "answer": [{"tool": "open_url", "url": "네이버"}, {"tool": "click", "target": "증권"}, {"tool": "get", "type": "text", "target": "삼성전자 주가", "variable": "var1"}, {"tool": "save", "type": "excel", "data": "var1", "cell": "A1"}]}
{"request": "쿠팡에서 무선 이어폰 찾아서 상품명이랑 가격을 가격비교.docx로 저장", "answer": [{"tool": "open_url", "url": "쿠팡"}, {"tool": "search", "keyword": "무선 이어폰"}, {"tool": "get", "type": "table", "target": "상품명과 가격", "variable": "var1"}, {"tool": "save", "type": "word", "data": "var1", "path": "가격비교.docx"}]}

--------------------------------------
[표현 생성 규칙]

1. 하나의 Intent에 대해 문장 구조와 표현 방식 자체가 다른 request를 생성한다.
2. 단어만 치환한 문장을 반복하지 않는다.
3. 실제 사용자가 자연스럽게 입력할 수 있는 문장으로 생성한다.
4. 표현이 달라져도 업무 의도가 같으면 동일한 Tool Sequence를 사용한다.
5. request의 요구사항을 모두 수행하도록 Tool Sequence를 구성한다.
6. 생략/축약 표현에서도 사이트명과 검색 키워드는 생략하지 않는다. 생략 대상은 동사, 조사, 저장 방식 설명 등이다.

[표현 유형 및 분포 (50개 기준)]
- 기본 표현: 10개
- 구어체: 8개
- 어순 변화 (목적어 위치 변경 포함): 7개
- 동의어 (검색→찾아서/조회, 저장→넣어/정리/옮겨 등): 5개
- 짧은 명령: 5개
- 복합 자연어 (긴 자연어, 여러 행동이 결합된 표현 포함): 8개
- 생략/축약: 5개
- 기타 실제 현업 표현 (업무 맥락 포함 요청 등): 2개

--------------------------------------
[생성 요청]

생성 조건:
- 서로 다른 request 50개를 생성한다.
- 모든 request는 아래의 Intent와 Tool Sequence 구조를 따른다.
- 위의 url, keyword, target, type, 분포 규칙을 모두 적용한다.
- JSONL 형식으로만 출력하며, 설명이나 주석을 추가하지 않는다.
