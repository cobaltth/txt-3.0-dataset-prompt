너는 beSRT TXT 3.0의 AI Agent 학습용 데이터셋을 설계하고 생성하는 전문가다.

TXT 3.0은 기존 End-to-end 방식이 아니라 Tool Calling 방식으로 동작한다.

사용자의 자연어 요청을 입력으로 받아 사용자의 의도를 파악하고,
사전에 정의된 Tool을 적절한 순서로 호출하여 업무를 수행한다.

따라서 데이터셋의 핵심 목적은
"다양한 자연어 표현 → 동일한 의도 → 동일한 Tool Calling Sequence"
관계를 학습시키는 것이다.

앞으로 제공하는 Tool 정의, 데이터 형식, 생성 규칙, 예시를 모두
하나의 데이터셋 생성 규칙으로 통합해서 기억하고 이후 데이터 생성에 적용해라.

지금은 데이터를 생성하지 말고 위 목적을 이해했다고만 답해라.

--------------------------------------

다음은 TXT 3.0에서 사용할 수 있는 Tool 목록이다.

[Tool 1]
open_url
설명: 웹사이트를 연다. 사용자가 입력한 웹사이트 이름을 실제 URL로 변환하고 페이지 로딩을 위한 delay를 자동으로 삽입한다.
파라미터:
* url: 열고자 하는 웹사이트

[Tool 2]
click
설명: 웹페이지에서 지정한 대상을 클릭한다. target에 해당하는 HTML 요소를 파싱하여 클릭한다.
파라미터:
* target: 클릭하고자 하는 대상

[Tool 3]
get
설명: 웹페이지에서 데이터를 가져온다. type에 따라 텍스트 또는 표 데이터를 가져오며, 가져온 결과를 지정한 변수에 저장한다.
파라미터:
* type: 가져올 데이터의 종류 (text 또는 table)
* target: 데이터를 가져올 대상
* variable: 가져온 데이터를 저장할 변수명

[Tool 4]
save
설명: 데이터를 파일로 저장한다. type에 따라 Word 또는 Excel 파일로 저장한다.
파라미터:
* type: 저장할 파일의 종류 (word 또는 excel)
* data: 저장할 데이터 또는 변수
* path: 저장할 파일 경로 또는 파일명 (optional)
* cell: Excel 데이터를 저장할 셀 주소 (optional)

[Tool 5]
type
설명: 문자열을 키보드로 입력한다.
파라미터:
* text: 키보드로 입력할 문자열

[Tool 6]
press_key
설명: 지정한 키 또는 단축키를 누른다.
파라미터:
* key: 누를 키 또는 hot key

[Tool 7]
search
설명: 웹페이지에서 검색한다. 검색창 클릭, 키워드 입력, Enter 입력 과정을 하나의 Tool로 수행한다.
파라미터:
* keyword: 검색할 키워드

--------------------------------------

Tool 사용 원칙
1. 반드시 위에서 정의한 7개의 Tool만 사용한다.
2. 각 Tool에서 정의되지 않은 argument를 생성하지 않는다.
3. argument 이름은 반드시 다음 정의를 따른다.
open_url(url)
click(target)
get(type, target, variable)
save(type, data, path, cell)
type(text)
press_key(key)
search(keyword)

4. path, cell처럼 optional인 argument는 필요한 경우에만 출력한다.
5. Tool의 argument 순서와 의미를 임의로 변경하지 않는다.
6. 사용자의 요청에 필요한 Tool만 호출한다.
7. 불필요한 Tool을 추가하지 않는다.
8. 하나의 고수준 Tool이 이미 존재하는 경우 불필요하게 저수준 Tool로 분해하지 않는다.
예: 검색 → search(keyword)
click("검색창") + type(keyword) + press_key("Enter")로 분해하지 않는다.
9. 사용자의 요청에 여러 작업이 포함된 경우 필요한 Tool을 논리적인 순서로 호출한다.
10. 앞선 Tool의 결과가 다음 Tool의 입력으로 필요한 경우 변수명을 활용하여 연결한다.
예:
get(..., variable="result")
→ save(..., data="result", ...)

이와 같이 Tool 간 데이터 흐름을 유지한다.

--------------------------------------

데이터셋은 다음 JSON 구조를 사용한다.

{
  "request": "사용자의 자연어 요청",
  "answer": [
    {
      "tool": "Tool 이름",
      "arg_1": "값",
      "arg_2": "값"
    },
    {
      "tool": "Tool 이름",
      "arg_1": "값"
    }
  ]
}

필요한 경우 arg_3까지 사용할 수 있다.

예:
{
  "request": "네이버에서 삼성전자를 검색해서 결과를 엑셀 A1에 저장해줘",
  "answer": [
    {
      "tool": "open_url",
      "url": "네이버"
    },
    {
      "tool": "search",
      "keyword": "삼성전자"
    },
    {
      "tool": "get",
      "type": "text",
      "target": "검색 결과",
      "variable": "result"
    },
    {
      "tool": "save",
      "type": "excel",
      "data": "result",
      "cell": "A1"
    }
  ]
}

--------------------------------------

데이터 생성 시 다음 규칙을 반드시 적용한다.

1. 하나의 Intent에 대해 다양한 자연어 표현을 생성한다.

2. 다음 표현 변형을 적극적으로 포함한다.
- 기본 표현
- 구어체
- 짧은 명령형
- 긴 자연어
- 어순 변경
- 동의어
- 목적어 위치 변경
- 생략된 표현
- 여러 행동이 결합된 표현
- 실제 현업 사용자가 말할 법한 표현

3. 표현이 달라져도 동일한 업무 의도라면 동일한 Tool Sequence를 사용한다.

4. 단순히 단어만 치환하여 만든 어색한 문장을 반복 생성하지 않는다.

5. 실제 사용자가 자연스럽게 입력할 수 있는 문장을 생성한다.

6. request에 포함된 요구사항을 모두 수행할 수 있도록 Tool Sequence를 구성한다.

7. 필요하지 않은 Tool을 추가하지 않는다.

8. Tool의 순서를 임의로 변경하지 않는다.

9. 존재하지 않는 Tool이나 파라미터를 생성하지 않는다.

10. argument 이름은 반드시 다음 정의를 따른다.
open_url(url)
click(target)
get(type, target, variable)
save(type, data, path, cell)
type(text)
press_key(key)
search(keyword)

11. answer는 반드시 지정된 JSON 형식을 따른다.

--------------------------------------

각 Intent를 생성할 때 다음과 같은 분포를 고려한다.

기본 표현       20%
구어체           15%
어순 변화        15%
동의어           10%
짧은 명령        10%
복합 자연어      15%
생략/축약        10%
기타 실제 표현    5%

단순한 단어 치환으로 동일한 문장을 반복하지 말고
문장의 구조와 표현 방식 자체를 다양화한다.

--------------------------------------

이제 다음 업무 Intent에 대한 데이터셋을 생성해라.

Intent:
"웹에서 특정 키워드를 검색하고 검색 결과를 Excel에 저장한다."

생성 조건:
- 1개의 Intent에 대해 50개의 서로 다른 request 생성
- 모든 request는 동일한 업무 목적을 가져야 한다.
- 표현은 최대한 다양하게 구성한다.
- 각 request에 대응하는 answer를 생성한다.
- answer는 실제 Tool 실행 순서를 반영해야 한다.
- 출력은 JSONL 형식으로만 출력한다.
- 설명이나 주석을 추가하지 않는다.
